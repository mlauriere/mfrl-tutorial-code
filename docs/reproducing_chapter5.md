# Reproducing the Chapter 5 figures

This repository contains the cybersecurity Q-learning, cybersecurity DDPG and
discrete distribution-planning implementations, their numerical configurations,
and the revised book plotting code. No numerical datasets, training histories,
network checkpoints or generated figures are distributed.

Run the experiments once to generate local results. Then assemble or adjust the
figures from those results without training, policy inference or simulator calls.
All required source and configuration files are included in this repository.

## Runtime and working directory

Run from the repository root with an existing environment satisfying
`requirements.txt` / `pyproject.toml`. The numerical runs use NumPy, SciPy,
Matplotlib, Gymnasium, Torch and PyYAML. CPU is the configured device. Nothing in
the commands below installs dependencies or changes an environment.

```bash
export PYTHONPATH="$PWD/src"
export MPLCONFIGDIR="$PWD/outputs/matplotlib-cache"
export OMP_NUM_THREADS=1
export OPENBLAS_NUM_THREADS=1
export MKL_NUM_THREADS=1
export VECLIB_MAXIMUM_THREADS=1
```

For a complete reproduction, record `git rev-parse HEAD`, the environment/library
versions, and the actual output directory printed by each command. Existing
training wrappers write resolved configurations, run logs and manifests.

## 1. Generate the numerical results locally

These are full experiments and can be long, especially asynchronous Q-learning.
They are never launched by imports or plotting. Run each command explicitly:

```bash
python -B -m mfrl_tutorial.cybersecurity_qlearning --config configs/cyber_qlearning_without_cn.yaml
python -B -m mfrl_tutorial.cybersecurity_qlearning --config configs/cyber_qlearning_with_cn.yaml

python -B -m mfrl_tutorial.cybersecurity_ddpg --config configs/cyber_ddpg_without_cn.yaml
python -B -m mfrl_tutorial.cybersecurity_ddpg --config configs/cyber_ddpg_with_cn.yaml

python -B -m mfrl_tutorial.distribution_planning_ddpg --config configs/distribution_planning_without_cn.yaml
python -B -m mfrl_tutorial.distribution_planning_ddpg --config configs/distribution_planning_with_cn.yaml
```

Each prints its timestamped output directory. Keep those six directories and
their `plot_data/` contents locally. Outputs are excluded from Git.

| Experiment | Configuration and interpretation |
|---|---|
| Cybersecurity Q-learning | T=10, dt=0.2, mesh resolution 30, two action levels per coordinate. Discount convention rho=-log(0.5)/0.1 gives gamma=0.25. SyncFull and SyncGreedy: 5000 iterations each; AsyncTraj: 400000. The three solvers run sequentially in their documented order. |
| Cybersecurity DDPG | T=10, dt=0.1, gamma=0.5. Actor and critic hidden layers [32,32], actor/critic learning rates 0.001/0.002, initial target update coefficient 0.005, 500 episode index limit. |
| Distribution planning | Eleven states, three actions per state, T=50, dt=1, gamma=0.99. Full network definitions are in the YAML configurations; actor hidden layers [128,128,128], actor/critic learning rates 0.0005/0.001, 3000 episode index limit. |
| Cybersecurity CN | Attack intensity follows the existing clipped Gaussian random walk with sigma=0.05 and bounds 0.7 and 1.3 times the default intensity 0.6. |
| Planning CN | Shifts -1,0,+1 have probabilities 0.05,0.9,0.05. No-CN configurations use a deterministic zero shift. |

All six supplied configurations use seed 1. DDPG uses inclusive episode loops:
indices 0 through 500 or 3000. The configurations specify the optimizer,
learning-rate schedules, exploration, replay sampling and Q-table update rules.
Both Q-learning configurations use state-mesh resolution 30.

## 2. Assemble the revised book figures

Replace the six placeholder paths below with the directories printed above.
These are directories generated by users, not files supplied by this repository.

```bash
python -B -m mfrl_tutorial.chapter5_figures \
  --cyber-q-nocn outputs/cyber_qlearning_without_cn/YOUR_TIMESTAMP \
  --cyber-q-cn outputs/cyber_qlearning_with_cn/YOUR_TIMESTAMP \
  --cyber-ddpg-nocn outputs/cyber_ddpg_without_cn/YOUR_TIMESTAMP \
  --cyber-ddpg-cn outputs/cyber_ddpg_with_cn/YOUR_TIMESTAMP \
  --planning-nocn outputs/distribution_planning_without_cn/YOUR_TIMESTAMP \
  --planning-cn outputs/distribution_planning_with_cn/YOUR_TIMESTAMP \
  --output outputs/chapter5_figures
```

To plot only one example, supply only its run-directory arguments. Supply both
noise conditions to reproduce the paired DDPG/planning training figures. The
command verifies archive hashes and schemas, checks configurations against the
supplied settings, and requires final evaluation/surface exports for full runs.
It writes PDF/PNG figures and `chapter5_figure_manifest.json`, recording input
hashes, iterations, color scales and smoothing. A failed redraw leaves an
`in_progress` manifest rather than a stale success record.

## Evaluation and display conventions

- Costs are negatives of undiscounted episode total rewards. Discounting is
  used internally in learning targets, not in these displayed episode totals.
- Q-learning evaluates one rollout for each of four starts, at the existing
  evaluation times. Synchronous solvers have evaluation costs, not artificial
  training-cost histories. Q differences are also saved locally.
- Cybersecurity DDPG evaluates five rollouts per start; their mean over four
  starts forms the evaluation curve. As in the original implementation, its
  illustrated trajectories are the last rollout per start. Attack-rate paths
  are recorded alongside the matching population paths.
- Planning evaluates five rollouts per start and illustrates the first one.
  Its common-noise path and endpoint actions belong to that same trajectory.
  Actions are from the online actor used for evaluation. The cumulative-noise
  step curve includes zero at t=0 and accumulates the first n shifts at t=n*dt.
- Blue denotes raw training costs, dark blue a solid moving average and bright
  dashed red evaluation costs. Moving averages use 20 entries with valid
  convolution, retaining the original index alignment. DDPG has no additional
  smoothing.
- AsyncTraj applies an additional centered integral average of the MA20
  polyline over 5000 iteration units, with symmetric shorter endpoint windows.
  This matches the revised display convention. It is not a raw 5000-sample
  moving average. It is computed from the saved numerical MA20 curve.
- Cybersecurity trajectories retain state colors, with thicker dashed ODE
  references, side row labels, shared labels and extra unlabeled grid lines.
  The references use constant attack intensity, including in CN comparisons.
- Simplex exports retain numerical values, NaN masks and exact color limits.
  Displayed colorbar labels use three decimals; limits are not rounded. The
  Q-learning book panel shows learned RL surfaces only. DDPG shows learned and
  ODE reference surfaces; the ODE reference is not a discrete Q-learning optimum.
- Planning shows aligned filled target bars and green initial/red terminal
  outlines, with no time-average overlay. Actions use a separate teal/gold/gray
  palette. State indices and labels are shared consistently.

## Local data contract

`chapter5_run.json` stores the resolved configuration and example identity.
Each `plot_data/` contains numerical NPZ snapshots, JSON descriptors and
`latest_KIND.json` pointers. Descriptors record iteration/episode, SHA-256,
array shapes/dtypes and evaluation conventions. Arrays load with
`allow_pickle=False`; plotting requires no model checkpoint or pickled data.

Q-learning puts exports inside each solver directory and retains `Q_table.npy`.
DDPG exports also include `networks_final.pt` with final online/target network
state dictionaries. These are available for later evaluation, not a complete
optimizer/RNG checkpoint for exact training resumption. Planning retains its
legacy object-NPY snapshots for compatibility; the new plot command reads only
the safe numerical exports. Histories are saved at existing plot checkpoints
and at normal training completion. Evaluation arrays are saved at existing
evaluation checkpoints; no extra stochastic evaluations are introduced.

## Bounded checks and limitations

The existing smoke configurations exercise short runs and produce local exports:

```bash
python -B -m mfrl_tutorial.cybersecurity_qlearning --config configs/smoke_cyber_qlearning.yaml
python -B -m mfrl_tutorial.cybersecurity_ddpg --config configs/smoke_cyber_ddpg.yaml
python -B -m mfrl_tutorial.distribution_planning_ddpg --config configs/smoke_distribution_planning.yaml
```

Use the printed smoke directories with the corresponding figure arguments and
`--allow-partial`. That option explicitly identifies outputs as custom/smoke
results in the manifest; it does not establish a book-scale learning result.
Plotting never fills in missing data by training a policy.

Verification covers full cybersecurity training for both noise conditions,
short training checks for all three methods, matching saved-array exports,
distribution-planning trajectory replay and figure generation from local data.
In full cybersecurity checks, final trajectories and evaluation costs agreed
with the reference figures within 1e-7; all compared heatmap colors matched.
This is a numerical comparison with the plotted reference curves, not a claim
of byte-identical outputs across machines. Full distribution-planning
retraining is not included in that full-run verification.

One CPU check used Python 3.11.13, NumPy 1.26.4, SciPy 1.17.1, Matplotlib 3.11.0,
Torch 2.2.2, Gymnasium 1.3.0 and PyYAML 6.0.3. With one numerical-library thread
per process, each full cybersecurity Q-learning condition took about 21–22
minutes and each DDPG condition about four minutes. These timings are examples,
not runtime guarantees for other machines.

Library/platform differences can change stochastic trajectories or PDF bytes.
Keep the generated data, configurations and manifests locally when reporting
results. No external dataset or model download is needed.
